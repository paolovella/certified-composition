## Plan

From PLAN-2026-10 §7 and §11 (0.6). On branch `g0/gate`, which builds on the unmerged chain
`g0/lean-435` → `p0-09/deprecations` → `spike/sail`. It merges only under the user's key.

1. **No silent skips.** `tools/ci.sh` prints every step it does not run, with the reason:
   `ABSENT: <tool>` or `DEFERRED: heavy runner`. `--require-heavy` turns ABSENT into a failure
   for the heavy runner. The Rust cross-check, Verus and the mathlib build are the heavy steps.
2. **certcheck in CI.** A step builds `certcheck` and runs all seven documented examples. The
   accepted one must exit 0, and each rejected one must exit 3 with the checker named in the
   README. Found while planning: `rejected/secret-branch.uc` is *accepted* when run as the
   README says. It is rejected only with `--secret pw`, which the README never mentions.
   `secret-leak.uc` without the flag is rejected by the string checker, not as a leak. So that
   gets a correction of record in the README, and the step runs the secret cases with the flag.
3. **Base-branch gate.** `tools/gate/base-gate.sh BASE PR` copies the PR tree, overlays BASE's
   gate code (`tools/` and `.github/`, minus the data PRs may change: `tools/axioms.expected`
   and `tools/receipts/`), and runs `tools/ci.sh --fast` there. Only the gate runs, in its own
   two extra checks:
   - **Ring 0 classifier.** Paths changed against BASE that match CLAUDE.md's Ring 0 list are
     printed, and the check fails, saying "needs the user's key".
   - **Manifest additions only.** No line of BASE's `tools/axioms.expected` may vanish or change.
4. **Workflow.** `.github/workflows/gate.yml` runs on `pull_request_target`, so the workflow and
   the gate come from master and a PR cannot edit them. Two checkouts, base and PR head, both
   with `persist-credentials: false`; `permissions: contents: read`; no secrets. The PR's code is
   built, so the job must hold nothing worth stealing, and the workflow says so. A `heavy` job
   runs on `[self-hosted, heavy]` with `--require-heavy`. With no runner online it waits, so a
   required heavy check fails closed.
5. **Witnesses.** `tools/gate/base-gate-witness.sh`: the gate passes an unmodified PR (accepted).
   It fails a PR that weakens `tools/ci.sh` to `exit 0` *and* breaks a proof, because master's
   `ci.sh` judges it (refused). It flags a PR that touches only `CLAUDE.md` as Ring 0, and fails
   a PR that drops a manifest line. The live acceptance (a weakening PR on GitHub judged by
   master's gate) can run only after `gate.yml` is on master. It is recorded as pending, not done.
6. **Left to the user, as settings:** branch protection requiring `gate` (and `heavy`),
   registering the WSL box as a `heavy` runner, and what the "user's key" is mechanically.
   Agents push with the user's credentials, so a GitHub approval proves nothing; a commit signed
   by a key agents do not hold would. Proposed in the Log, not built.
