## Plan

**The claim, exactly, as RC-01's.** "This C function, read into L and compiled by L's certified pipeline, is constant-time on the machine
model." Not "libsodium is constant-time". Constant-time is L's observation on `rvLang`: PCs, addresses, instruction count, termination.

**The user's go, 2026-11-08**, after RC-01's account recommended output arrays first.

**The function.** `sodium_add` in `src/libsodium/sodium/utils.c` at `1.0.20-RELEASE` (sha256 `62ef6a5e…756d96`, fetched from the tag
and to be vendored and hashed in the build, as `verify.c` is). With `HAVE_AMD64_ASM` undefined, as on RISC-V:

```c
size_t        i;
uint_fast16_t c = 0U;
for (i = 0U; i < len; i++) {
    c += (uint_fast16_t) a[i] + (uint_fast16_t) b[i];
    a[i] = (unsigned char) c;
    c >>= 8;
}
```

Little-endian addition of two byte strings, `a` in place. The carry `c` is secret and loop-carried, the index public. `len` is a
parameter, so it is read at a **stated length**, as `crypto_verify_16_BYTES` was a stated define: **32**, from a real call site.
`crypto_core_ed25519_scalar_add` (`crypto_core/ed25519/core_ed25519.c`, line 164) calls `sodium_add(x_, y_,
crypto_core_ed25519_SCALARBYTES)`, and `crypto_core_ed25519.h` defines it as `32`. Its buffers are 64 bytes, of which the add touches
the first 32. Four words, which `loadB` already masks. Both files are to be pinned in step 1.

**How an output is observed, with no kernel change.** `Ev.emit (sink) (data : List Nat)` exists. A program's output array is emitted
as `.emit "out" bytes` just before the result event.
- **Source:** `Prog` gains `outs : List String`, input words that the program may write. At the end, the run emits their bytes, then
  `ret`. With `outs = []` nothing is emitted, so every existing program, proof and image is unchanged.
- **Machine:** the Linux `write` syscall (`a7 = 64`, `a0 = 1`), whose bytes QEMU user mode prints to stdout, so the test compares them
  directly. `rvLang`'s step gains an outcome that emits an event and continues. It leaks the addresses it reads, as `ld` does, and
  aborts on any other file descriptor or on memory it cannot read.
- **Constant time:** an observer `noOut` reads every channel but `.ext "ret"` and `.emit "out"`. The output depends on the secret
  by design, as the result did for `crypto_verify_16`. Its *length* and timing do not: the channel is still seen, only its payload
  is not read, because an observer chooses channels, never payloads.

**Steps, riskiest first.** Each ends with a report in the log.
1. **The reading, on paper,** against the pinned `utils.c`: the branch, `+=` and the casts, `(unsigned char) c` as `& 255`,
   `uint_fast16_t` as a word (LP64 glibc, as `RC-01-READING` §2), `a` read and written, `b` read-only, the stated length. What
   C's aliasing would allow (`a == b`) and what the reading assumes (distinct arrays, by the subset).
2. **The machine:** `sb` and the `write` syscall in `rvLang`, each compared with QEMU in `rv_diff.py`, which must capture stdout, with
   a broken model per rule (a store of the wrong byte, a `write` of the wrong length, a `write` that leaks nothing).
3. **The language:** `storeB names e v`, byte `e` of the words `names` set to `v`'s low byte; `Prog.outs` and its emit at the end;
   the checker (index public; a written word's taint rises with `v`'s); noninterference. Then through the slots pass (`sb` into the
   word's slot) and the lowering, with an epilogue `write` over the output slots when `outs ≠ []`. Every existing image must be
   byte-for-byte unchanged.
4. **Constant time:** `noOut`, and `ctCheck`'s certificate for it, reusing `ctCheck_relView`'s argument. Witnesses each way.
5. **The front end:** `+`, `+=`, `>>=`, `a[i] = e` on a non-`const` pointer parameter, `(uint_fast16_t)` and `(unsigned char)`
   casts, and a `size_t` index. `sodium_add` read by `decide`, plus refused variants.
6. **`sodium_add`, certified on its literal image,** by `relView_transfer` and `bound_transfer`.
   - Under QEMU, on many inputs: traces and costs independent of the secrets, and the printed bytes equal to the model's.
   - Clang's compiled original, run natively, gives the same bytes on every pair.
   - **Teeth:** a variant that stops at the first zero carry is refused, and its image is seen to leak.
7. **The account.**

**Time.** Each kernel-evaluated witness is re-checked by route 2's six kernels. Concrete-run witnesses stay short, as `CTBytes`'s
were, and the QEMU tests carry the many-input evidence. Budgets are not raised without the user's word.
