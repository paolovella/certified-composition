## Plan

From PLAN-2026-10 §7 and §8 (Mutant hunter). On branch `g0/mutants`, which builds on
`p0-04/registry`.

1. **Operators.** `tools/mutants.py`, fixed and mechanical, never written by a model. Each
   result position (after `=>`, `then`, `else`) in each registry checker is flipped:
   `none` → `some default`, `false` → `true` (refuse→accept), and `some …` → `none`,
   `true` → `false` (accept→refuse). The first count: **318 sites in 35 of the 37 checkers**.
   `pathCheck` (`flat steps`) and `scheck` (a bind) have no site.
2. **Verdicts.** Each mutant is built in a copy of `conf-typing`:
   - **killed:** the build fails outside the mutated definition;
   - **stillborn:** the mutated definition does not elaborate;
   - **survived:** it builds;
   - **unexplained:** it fails without a located error.
   The accepted witness is the unmutated copy, which must build first or there is no verdict.
   The refused witness is any killed mutant.
3. **Survivors.** A survivor means no theorem constrains that rule. Each one gets a witness
   that kills it, or, if the rule is genuinely free (dead code, or a result no proof
   depends on), an item that says so.
4. **Ratchet.** `tools/mutants.expected` holds the per-site verdicts. Under §7 the killed count
   never decreases. The run is too slow for every `ci.sh`, so it goes to the heavy runner, and a
   check-claims guard keeps the committed table matching the site list.

## Log

- 2026-10-26, branch `g0/mutants`.
  - **First run** (`p005-mutants-all`, 204 s, 6 jobs): 318 built, 299 killed, 16 stillborn,
    **3 survived**:
    - `secCheckD` (`SecTyD.lean:179`): `.skip => true` → `false`;
    - `ucheckNI` (`UnifiedNI.lean:236`): the same;
    - `dbcheckNaive` (`DbInjection.lean:209`): `.emitP … => some …` → `none`.
    In each case the checker could refuse that construct and every proof still went through,
    because no theorem accepts a program that uses it. All 16 stillborn mutants were in
    `tcheck`/`tcheckW`: the first accept→refuse form, `(fun _ => none) <| some x`, left `x`'s
    type undetermined. It is now `Option.filter (fun _ => false) <| some x`, which takes its
    type from context.
  - **Survivors killed** by three accepting witnesses in `ConfTyping/Witnesses.lean`
    (`secCheckD_accepts_skip`, `ucheckNI_accepts_skip`, `dbcheckNaive_accepts_emitP`). The
    manifest gains exactly those 3.
  - **Second run** (`p005-mutants-all2`, 195 s): **318 built, 318 killed**, 0 stillborn, 0
    survived, 0 unexplained. `tools/mutants.expected` holds the per-site verdicts
    (`p005-mutants-write`).
  - **Witnesses of the runner** (`tools/gate/mutants-witness.sh`). Accepted: `secCheckD`'s
    mutant is killed. Refused: with `secCheckD_accepts_skip` deleted it survives. The runner also
    refuses to give a verdict when the unmutated copy does not build. The first version of the
    refused case tripped that by leaving a dangling doc comment, so the check did its job.
  - **CI**: `ci.sh` runs `mutants.py --check` and the runner witnesses in the full run. They are
    DEFERRED under `--fast`.
  - **Table drift.** check-claims (j) compares the table's sites with today's checkers on every
    run, with no build: `mutants.py --sites-check`, plus a self-test case (69).
  - **Limits.** Two operators on result positions only. Conditions are never negated, `&&` is
    never turned into `||`, and the arguments to recursive calls are never changed. Two
    checkers (`pathCheck`, `scheck`) have no site at all. A 100% kill rate with operators this
    weak is the stagnation signal of PLAN-2026-10 §8, so the next cycle should add condition
    negation.
