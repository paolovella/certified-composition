## Plan

From PLAN-2026-10 §2 and §7. On branch `g0/statements` (off `p0-08/kani`), merged only with the
user's key. The user's decision (2026-10-26): "allow sorry in the challenge file only".

1. **The challenge.** `workspace/Statements.lean` states each frozen theorem as
   `theorem Frozen.<name> : <statement> := sorry`, with the statement copied from the source.
   `workspace/StatementsProof.lean` proves each by citing the real theorem
   (`:= ConfTyping.<name>`). Both import the packages, since the statements mention their
   definitions. Neither is a default build target, so `lake check` and the export never see
   the challenge's `sorryAx`.
   First set: the soundness theorem of every registry checker that has one, plus
   `leakSafe_sound`, `source_certified` and `Bridge.comp_cert`. The set is the user's to change
   (G-0).
2. **`comparator.json`** at the root: `challenge_module` `Statements`, `solution_module`
   `StatementsProof`, the frozen names, `permitted_axioms` the standard three. `lake comparator`
   is a new required step in `ci.sh`, and a witness requires it to refuse a weakened copy.
3. **The `sorry` exemption is exactly one path**, `workspace/Statements.lean`, in the pre-commit
   hook and in the CI no-sorry step. CLAUDE.md's rule says so. A new check-claims guard (k)
   requires that every `sorry` in it is the whole body of a `Frozen.` theorem, that it
   declares nothing else, and that no file imports `Statements`. Self-test cases for each.
4. **`ring0.lock`.** A statement can be weakened without touching its text, by editing a
   definition it mentions. `tools/ring0-lock.sh` hashes the Ring 0 files (the challenge,
   `comparator.json`) and, through a metaprogram, every definition in each frozen statement's
   dependency closure inside the two packages. CI fails on any difference. A witness edits one
   such definition and expects a refusal.
5. Ratchet: the number of frozen statements never decreases (guard on `comparator.json`).
