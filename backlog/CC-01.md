## Plan

The user's word of 2026-11-06: "do c", after the cause was found. guard-selftest's time is the machine's process creation, not anything that
changed. Each case runs `check-claims`, which traces 3,611 commands, about 1,750 of them new processes, so a run starts about 350,000. At
`GUARD_JOBS=8` that measured 58 s, and the same tree measured 46 to 48 s in earlier CI runs. `check-claims` is byte-identical between `219e008` and
HEAD, and its per-case time is the same at both. The other options, 16 jobs or a 60 s budget, were set aside by the user for this one.

**Rewrites, each keeping its rule's meaning:**
1. **Namespaces (rule 1b, `qualify`):** one `awk` over every `ConfTyping` file, printing file and qualified name, in place of an `awk` per file, run
   twice. Both the outside-namespace and the duplicate checks read its output.
2. **Backlog fields (rule c):** one `awk` per item, which prints the missing keys, in place of six `grep`s and a seventh for the status.
3. **Cited names (rule 1c) and imported modules:** the sources and the map are read once into variables, and each name is matched with bash's
   substring test. Every cited name is `[A-Za-z0-9_]`, so a regex match and a substring match agree. In `"$mod.lean"` the `.` is a regex wildcard,
   matched as `?`.
   *As built, this changed* (see the log): the whole-text variable made things slower, so one `grep` first keeps only the lines that can match.

**Checks.** The old script is kept as a copy. Old and new run on the clean tree and on mutations that reach each rewritten rule, and their output
must be equal line for line. guard-selftest passes every case. Any rewritten rule without an accepted and a refused case in the self-test gets them.

## Log
- 2026-11-06, **done**. Full CI green (receipt `cc01-ci`), guard-selftest 32 s against its budget of 49 s.
  - **The four rewrites.** One `awk` for every namespace. One `awk` per backlog item. For the cited names, one `grep -rhF` with every name, keeping only the lines that hold one, and then a bash substring test per name in those lines. For the modules, two `grep -F`s, then the same test. Every rewritten rule prints its old messages.
  - **A wrong first version.** Reading every source into one variable and testing `*"$name"*` against it made `check-claims` 7.3 s and the self-test 138 to 149 s. Bash's pattern matching on a large string is far slower than the `grep` it replaced. Filtering with one `grep` first fixed it.
  - **Equal verdicts** (`research/2026-11/cc01_equiv.py`): the old and new scripts print the same lines in all 17 cases. They cover the clean tree; each rewritten rule both ways; two missing backlog fields, for the order of the messages; a key only mid-line; a cited name only in a comment, and only in a non-Lean file, both of which the old rule accepts and so does the new; and a module imported under a longer name. Three corner cases were closed before the comparison: `grep -r` reads non-Lean files too; a regex `.` does not match a newline; and joining files must not let a name span two of them.
  - **Witnesses**, five new in `guard-selftest.sh`, for rules that had no case: a declaration outside the namespace, the same name nested in another namespace (accepted), a backlog item losing a field other than status, a cited name renamed everywhere, and a cited module not imported. Each gives exactly one drift line, that rule's.
  - **Time.** `check-claims` 2.5 to 1.85 s. guard-selftest 34 to 35 s for 103 cases, from 52 to 58 s for 98, with `GUARD_JOBS` and the budget unchanged.
