## Plan

Opened by the P0-09 correction (2026-10-26). `transport-kernel` builds the `transport-calculus`
sources under its own toolchain, so while it stays on 4.31, `transport-calculus` can use only
names that exist in both 4.31 and 4.35. That leaves it 65 deprecation warnings.

On branch `g0/tk-435` (off `g0/mutants`), in its own worktree so that the 4.31 build cache the
other branches use is untouched.

1. **Pins.** `transport-kernel/lean-toolchain` → `v4.35.0`. mathlib `v4.35.0` (`56a0058555`) and
   Physlib `v4.35.0` (`af04d60bcd`) both have the tag, and Physlib's own manifest asks for
   mathlib `v4.35.0`. Physlib is pinned by commit, as now. `lake update`, then
   `lake exe cache get`.
2. **Build and count**, by the S-435 method: errors per module, deprecations. Re-prove what
   breaks without changing any statement. If the breakage is past one session, the kill rule
   applies: stay on 4.31 and record what was checked.
3. **Then P0-09's other half.** Redo the `transport-calculus` renames. Both toolchains are then
   4.35, so the 65 warnings can go.
4. **Docs and guards.** README's "`v4.31.0` with its mathlib" line and check-claims (h), which
   pins that sentence, move to the new version together. The manifest does not cover
   `transport-kernel` (mathlib); any footprint the docs state for it is checked by hand and
   recorded.
5. Full `tools/ci.sh` green, then push.
