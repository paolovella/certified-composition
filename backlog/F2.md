## Plan

From [FOUNDATION-2026-10-29](../research/2026-10/FOUNDATION-2026-10-29.md), item F2. On branch `f2/lawful` (from `ph1/ucmd-lang`, with F1 merged).

**The hole, proved first** (`conf-typing/ConfTyping/Vacuity.lean`). `bcheck` certifies
`vacProg` (emit to `out`, then a counted loop that checks `db`) with budget 12
(`vacProg_checks`). Under a policy refusing `db`, the run dies on the first check, a dead state
is frozen, the counter never moves, and `uexec` returns nothing at every fuel
(`vacProg_diverges`). So `ucmdLang` gives the empty record, and the certified program, which
did emit (`vacProg_emits_first`), carries both "emits nothing" and "costs 0"
(`vacProg_vacuous`). The hole goes through the checker, not only the kernel.

**Two facts that shape the fix.**
- `uexec`'s fuel bounds *depth*, not steps: `seq` hands the same `n` to both halves. A prefix
  is therefore defined by a fuel-reporting twin, not by counting steps.
- `ucmdLang`'s observation lists every read before every emit, and every branch bit before
  every address. When a run extends, new items land in the middle of each list, so *no*
  prefix law can hold of this layout. F2 needs one event trace and one leakage trace in
  program order (LAdapter's docstring lists this as a v1 limit).

**Steps.**
1. **Kernel laws** (`l-core/LCore/Kernel/Lang.lean`, Ring 0). `Lang.Lawful L`, for `n ≤ n'`:
   events and leakage of `run n` are prefixes of those of `run n'`; cost is monotone; a
   finished run (`out ≠ fuel`) is stable. Plus **divergence costs**: for each program there is
   a `d` with `n ≤ cost + d` whenever `run n` is out of fuel, so a run that never finishes has
   unbounded cost and fails every `bound`.
   Kernel theorem `bound_finishes`: on a lawful language, `Cert.bound k p` implies every run of
   `p` finishes at some fuel. Witnesses: a lawful toy; the constant-empty language refused by
   the divergence law; a language whose lists grow in the middle refused by the prefix law.
2. **UCmd, instrumented** (`conf-typing`, Ring 1). `uexecT`: `uexec`'s twin that returns, at
   every fuel, the state reached, the cost so far, one event trace and one leakage trace in
   program order, and the outcome (done, abort, or fuel). `uexec` is locked meaning, so it is
   not edited. Proved: on finished runs `uexecT` agrees with `uexec` (state, cost), and its
   traces project to `uexec`'s branch trace, `uaddrs`, reads and sink. Proved lawful, with
   `d = size c`.
3. **`ucmdLang` on `uexecT`**, and `bcheck_lcore` re-proved over partial runs:
   - `bound`: on a lawful language, `Cert.bound k p` forces every run of `p` to finish
     (step 1). `vacProg` under `refuseAll` never finishes, so on the fixed `ucmdLang` its
     budget certificate is **false**, and `bcheck_lcore` as stated cannot be re-proved. The
     fix then belongs in the language, not the proof. Two options, chosen when reached: abort
     halts the run (PLAN-2026-10 PH3's halting abort, brought forward to UCmd's twin), or
     `bcheck` refuses a `check` inside a counted loop.
   - `trace (mediated π)`: a partial run's reads are an initial segment of a finished run's,
     or of the reads up to the abort; the monitor invariant holds along partial runs.
   - `rel`: noninterference over partial runs at equal fuel.
4. **Flip the witness.** `vacProg_vacuous` becomes its negation; a guard keeps the pair.

**What this item may find**, stated before it does: step 3 may show that the existing UCmd
certificates are not true of the program's real behaviour once partial runs count. That is the
point of F2. The kill rule covers only the case where the twin cannot be matched to `uexec`.
