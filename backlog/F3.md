## Plan

From [FOUNDATION-2026-10-29](../research/2026-10/FOUNDATION-2026-10-29.md), item F3. On branch `f3/land` (from `f2/lawful`).

**The gap.** `rel_transfer` concludes `T.run m p' (enc i) = T.run m p' (enc i')`, a fact about
the images of source inputs. A target input no source input encodes to is unconstrained, and
an attacker picks exactly that input. The same holds for `trace_transfer` and
`bound_transfer`, so a compiled program never carries a certificate in its own language.

**The two designs, judged before code.**
- (a) A decoder `dec : T.In → Option S.In`, so every target input decodes. Too strong for a
  real back end: a RISC-V state with garbage in its registers decodes to nothing, and the
  honest claim is relative to well-formed states.
- (b) **Chosen.** Each language declares its admissible inputs (`Lang.Adm`, default all), the
  certificate shapes range over admissible inputs, and a pass must *cover* them:
  `enc` maps admissible to admissible, every admissible target input is an encoding of an
  admissible source input, and every Low-equal pair of admissible target inputs is the
  encoding of a Low-equal source pair. Then the transfers conclude `Cert.trace T Φ p'`,
  `Cert.rel T p'`, `Cert.bound T k' p'`, and composition holds at the certificate level: a
  certified target program is a certified source for the next pass.
  If F4 cannot meet the cover condition, that is the obstruction the kill rule asks for.

**Steps.**
1. Kernel (Ring 0): `Lang.Adm` with default `fun _ => True`; shapes over admissible inputs;
   `PassCert.enc_adm`, `cover`, `low_cover`; transfers concluding `Cert.X T`; `seq` composes
   the covers.
2. Witnesses: the toy passes cover; a pass whose `enc` misses an admissible target input on
   which the program leaks cannot cover (`leaky_misses`), and its target is not `rel` although
   the source is.
3. Adapters re-proved: `bcheck_lcore`, `bcheck_lcoreT`, Vacuity, P1. P1's slot machine takes
   the same store as input (`enc` is the identity), so it covers trivially. P1 stays between
   the old, non-lawful languages: moving it onto lawful ones is F4's first job.

## Log
- 2026-10-30, branch `f3/land`. **Design (b) built.**
  - Kernel (Ring 0): `Lang.Adm` (default: every input); the three shapes range over admissible
    inputs; `PassCert` gains `enc_adm`, `cover` and `low_cover`; `trace_transfer`,
    `rel_transfer` and `bound_transfer` now conclude `Cert.trace T Φ p'`, `Cert.rel T p'` and
    `Cert.bound T (t.cost k) p'`, certificates of the compiled program in its own language;
    `seq` composes the covers. The transfers and `seq` still use no axioms.
  - Witnesses: the toy passes cover (identity encoding); `chained_carries_bound` takes one
    pass's output certificate as the next pass's input, with no `seq` (composition at the
    certificate level). **Refused:** `leakyT` has a flag `leakyEnc` never sets. On the
    encodings `false` is indistinguishable (`leaky_rel_on_encodings`, exactly what the old
    `rel_transfer` concluded), yet the target leaks on a flagged input
    (`leaky_not_rel`), and no `PassCert toy leakyT` with that encoder exists (`no_leaky_pass`,
    via `leaky_misses`). That is the A2 hole, closed.
  - Adapters re-proved with the admissibility argument: `bcheck_lcore`, the four ports,
    `bcheck_lcoreT`, Vacuity. P1 covers trivially (`enc` is the identity, the slot machine
    takes the same store), and `ucmd_p1_carries` now concludes `Cert.bound`, `Cert.trace` and
    `Cert.rel` of the slot program on `slotLang`; its proof is unchanged, so guard (m) holds.
  - Still to judge on F4: whether a lowering whose target input really differs from the source
    input can meet `cover` and `low_cover`. That is this item's kill rule.
