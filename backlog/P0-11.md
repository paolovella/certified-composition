## Plan

On the user's word (2026-10-27): "make sure the checkers edits are green flagged with a limit".

Measured on `g0/statements`: `tools/ring0.lock` covers 587 constants. 197 of them are reached
only through the checkers that the frozen statements name (`costCheck` in `costCheck c = some
k → CostAtMost c k`). Checkers are Ring 1 in PLAN-2026-10 §1, but the lock makes each edit to
one a G-0 change. Locking them buys nothing: the comparator already forces every frozen
soundness theorem to be re-proved against the locked meaning, so a checker edit cannot weaken
what a statement says. The most it can do is refuse more, and the accept witnesses
(`tools/witnesses.expected`, kernel `decide` theorems) fail the build when it does.

1. **Split the lock** (`tools/gate/Ring0Lock.lean`). A frozen theorem `X_sound` names the
   checker `X`. The *meaning* is the dependency closure of the statements that does not pass
   through a checker; it stays in `tools/ring0.lock` (Ring 0), with the list of checkers. The
   rest, per checker, goes to `tools/checkers.lock`.
2. **`tools/checkers.lock` is data a PR may change**, like `tools/axioms.expected`. CI requires
   it to be current (`tools/ring0-lock.sh --check`; `--checkers` rewrites only it).
3. **The limit, in the base gate** (`checkers` rule): the number of checkers whose entries differ
   between the base's `checkers.lock` and the PR's must be at most 3 (`CHECKER_LIMIT` in
   `tools/gate/base-gate.sh`, Ring 0). More needs the user's key.
4. **`tools/mutants.expected` is data too**: a checker edit moves mutation sites, so the table
   must move with it. The gate's `mutants` rule requires every row of the PR's table to be
   `killed`; `mutants.py --sites-check` (check-claims) requires it to list today's sites, and
   the heavy runner recomputes it (`mutants.py --check`).
5. **Witnesses.** Lock: an equivalent `costCheck` edit leaves `ring0.lock` current, makes
   `checkers.lock` stale, and passes after `--checkers`; the `CostAtMost` edit is still refused.
   Gate: `checkers` accepts 1 changed checker and refuses 4; `mutants` accepts an all-killed table
   and refuses one with a survivor.
6. Docs: README "Frozen statements", the base-gate header, CHANGELOG; a check-claims guard that
   the README's limit equals `CHECKER_LIMIT`.

Not covered: the hosted gate runs `--fast`, which does not rebuild the mutant table, so the
`killed` rows are only recomputed on the heavy runner, which is not registered yet.
