## Plan

**The claim, exactly, for every write-up of this item.** "This C function, read into L and compiled by L's certified pipeline, is
constant-time on the machine model." **Not** "libsodium is constant-time": the libsodium people ship is compiled by Clang or GCC, which
nothing here checks, and an optimising compiler can turn constant-time C into leaky code. That is why the source uses `volatile`.
"Constant-time" here also means L's observation, which covers PCs, addresses, instruction count and termination on `rvLang`, and not
cycles, caches or speculation. A side agent raised the first point, on 2026-11-08.


The user's decision of 2026-11-06: "we need to work on real code now", then, of three options, **"Real C, at the source"**: a front end that reads a
subset of real C into L's language and checks it there. L-BYTES' route is to grow `sliceLang`, so the subset grows the slice language, and
each construct goes through to the bytes.

**The first real code: libsodium's constant-time compare.** `src/libsodium/crypto_verify/verify.c` at tag `1.0.20-RELEASE`, sha256
`44642761…568ea9`, the portable (non-SSE2) `crypto_verify_n`:

```c
const volatile unsigned char *volatile x = (const volatile unsigned char *volatile) x_;   /* and y */
volatile uint_fast16_t d = 0U;
int i;
for (i = 0; i < n; i++) { d |= x[i] ^ y[i]; }
return (1 & ((d - 1) >> 8)) - 1;
```

with `crypto_verify_16` calling it at `n = 16`. Small, used everywhere, and security-critical: its whole point is that its time and memory
accesses do not depend on the secret bytes.

**The certificate is not `rel`.** The function returns whether the buffers are equal, so its result depends on the secret by design, and
`rel` refuses it. **Constant-time is `Cert.relView lowIn f`**, with an observer `f` blind to the result channel. Leakage, cost and outcome
must still be the same, at every fuel. The kernel has the shape and `relView_transfer`, so **no kernel change is expected.** The checker
needs a variant that does not require a public result.

**What the slice language lacks, each a step through to the bytes:**
- **Operators:** `^`, `|`, `&`, `-` and logical `>>` by a constant. `rvLang` gains `xor`, `or`, `sub` and `srli`, each compared with QEMU in
  `rv_diff.py`, with a broken model per instruction.
- **Byte arrays as inputs:** two read-only arrays of `n` bytes, the secret ones, in the data segment. Loads of bytes, which `rvLang` gains as
  `lbu`. Fixed length, so no aliasing and no bounds to check: the index is the loop's.
- **An increasing index:** `for (i = 0; i < N; i++)` with a literal `N` and `i` not assigned in the body, read as BOUND-01's counted loop,
  with `i = N - c`. Its budget is constant.

**The reading of C, a trust assumption stated once.** The front end gives each construct of the subset a meaning in L.
- `unsigned char` loads are zero-extended.
- `uint_fast16_t` is 64 bits, as on glibc for riscv64 and x86-64. This is a platform fact, and it is stated.
- `int` arithmetic on the values here stays in range, which needs a side check.
- `volatile` has no meaning in L. It exists to stop an optimising compiler. L's pipeline does not optimise, so it is read and dropped, and
  that is said.

The reading is believed **only by testing**: the original C, compiled by clang, and L's program run on the same inputs must agree.

**Steps, riskiest first.** Each ends with a report.
1. **The subset and its reading, on paper,** against the pinned source, before any parser.
2. **The operators, through to the bytes,** one at a time, with `rv_diff.py` cases.
3. **Byte arrays and the increasing loop,** through to the bytes.
4. **The constant-time checker,** with an accepted and a refused witness per rule, and `relView` on the source.
5. **The front end:** a parser for the subset, in Lean, so the reading is code that can be checked. It must take `verify.c`'s function as
   written, including `volatile` and the casts.
6. **`crypto_verify_16`, certified:** constant-time and a constant budget on its literal image, by transfer.
   - Under QEMU, on many inputs: traces and costs independent of the secret bytes.
   - Results equal to clang's compiled original, run natively.
   - **Teeth:** a variant with an early exit on the first difference (`if (x[i] != y[i]) return -1;`) is refused, and its bytes are seen to leak.
7. **The account,** including what of C is still out of reach.
