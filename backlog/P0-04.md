## Plan

From PLAN-2026-10 §11 (0.4) and the house rule "every checker rule has an accepted witness and a
refused witness". On branch `p0-04/registry`, which builds on `g0/gate`. Here a *rule* is a
checker; per-rule-branch coverage is P0-05's job, which mutates the checkers.

1. **Computed registry.** `conf-typing/WitnessRegistry.lean`, a metaprogram like
   `AxiomManifest.lean`, finds every checker and every closed `decide`-style witness from the
   environment. Nothing is registered by hand (the header gives the definitions). It prints one
   row per checker and `registry: N checkers, M missing a witness`.
   First run (2026-10-26): **37 checkers, 17 missing a witness**: `alcheck2 bcheck costCheck
   dbcheck dbcheckNaive hcheck jcheckList jcheckW lcheck pathCheck pcheckW scheckA secCheckT
   tcheckW umcheck wcheck xcheck`. A grep for other phrasings found none of them.
2. **Fill them.** `ConfTyping/Witnesses.lean` gets one small program per missing side, each
   verdict by kernel `decide`. No existing proof changes. For `dbcheckNaive`, the naive checker
   kept to show it accepts an attack, the refused witness shows it is not vacuous either. For
   `lcheck` (the open `LeakFree` cell, P0-08), the witnesses are about its verdict, not its
   soundness.
3. **Gate.** `tools/witnesses.sh --check` runs the registry and fails unless it ends
   `0 missing`. It also commits the table as `tools/witnesses.expected`, so a checker that loses
   a witness, or a new checker that arrives without one, shows up as a diff. `ci.sh` runs it.
   The manifest gains the new theorems, additions only.
4. **Witnesses of the registry itself.** Accepted: the real tree, `0 missing`. Refused, as
   guard-selftest-style cases: delete one witness theorem and the check fails; add a checker
   with no witnesses and the check fails. A witness stated with a leading `∀` must not count.
