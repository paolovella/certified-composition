## Plan

1. Copy `transport-calculus/` and `conf-typing/` (sources only, no `.lake`) to a scratch dir,
   set both `lean-toolchain` files to `leanprover/lean4:v4.35.0`, and `lake build` each with
   `-KnoSorry`-free defaults, writing the full log through `tools/run-job.sh`.
2. Count: modules that fail, error messages by kind (renamed lemma, simp set change, `omega`
   / `decide` behaviour, deprecations as warnings), and declarations affected.
3. Rebuild the axiom manifest under 4.35 and diff it with `tools/axioms.expected`: a change in a
   footprint is a finding even if everything builds.
4. Check that `lake check` exists in 4.35 and what it reports on the copy (the gate the plan
   wants: P0-02).
5. Output `bench/s435.tsv` (module, errors, warnings, kinds) and a decision in Log: bump in
   place (P0-02) if breakage is small, else the plan's kill rule (> ~10% of modules: stay on
   4.31 and use external checkers on lean4export output).
6. Do not touch the real packages' toolchains here; that is P0-02 (G-0).

**Decision.** The kill rule (> ~10% of modules) does not fire: 1 of 96 modules breaks, with a
one-word fix. So **bump in place (P0-02)**. But P0-02 as written cannot meet its acceptance
("lake check passes"), and the bump is not footprint-neutral. Findings P0-02 has to take up
(G-0, for the user's decision):
1. Footprint regression: pin `BEq Int` in `Imp.lean` and re-prove the 6 `simp` proofs, or
   record the 11 claims as corrections of record. Either way, `tools/axioms.expected` changes
   with the bump.
2. `lake check` vs sibling path dependencies: put the packages under one workspace root that
   the sandbox mounts, or accept `--from-export` with an export built in CI (weaker, as above).
3. nanoda ~~needs a larger thread stack for `conf-typing` (`RUST_MIN_STACK`), set wherever it
   runs~~; with the default it rejects by crashing. *Corrected 2026-10-25 (see above): it
   needs one thread and an unlimited main stack, which `lake check --paranoid` cannot give it.*
4. 1156 deprecation renames (`if_pos`/`if_neg` → `ite_eq_left`/`ite_eq_right` etc.), as a
   follow-up that only removes warnings.
