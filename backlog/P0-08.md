## Plan

From PLAN-2026-10 §11 (0.8) and I-0001. On branch `p0-08/kani` (off `g0/tk-435`).

**A. The Kani loop search** (`cross-check/leak-kani`). One harness over every 5-node program,
loops included (MAXITER 2), ran symbolic execution for 1459–2098 s and never got a solver
verdict.
1. **Split by the root's tag.** `well_formed` caps every tag at `T_LOOP`, so nine cells, one
   per root tag `0..=8`, cover every program. A covering harness proves the cells exhaust
   `well_formed`. Each cell is its own `#[kani::proof]`, generated by a macro so the cells
   cannot differ except in the tag.
2. **Run each cell** through `tools/run-job.sh` with a 60-minute timeout, three at a time.
   Record symex time, VCCs, solver time and verdict per cell in `bench/kani-loops.tsv`.
3. **A cell that times out is split again,** by its root's children (`l`, `r`). If a cell
   cannot be finished at any split, that is the kill rule: record the bound reached.
4. **Vacuity witnesses, per cell family:** the same split for `accepted_programs_can_allocate`
   (an accepted program that allocates exists) and `some_program_leaks` (the space contains
   leaks). Both must be *refuted* somewhere, or "no counterexample" means nothing.

**B. `LeakFree` on aborting runs.** The acceptance allows "certified or ledgered". It is
ledgered: VULN-COVERAGE row 6 states the restriction, the conf-typing README states it at
"aborts on a refused `check`", and `allocThenCheck_accepted` witnesses it. Recorded as met by
the ledger. Certifying it (a stricter checker that refuses a `check` while anything is still
allocated) is left as an option, not done here.
