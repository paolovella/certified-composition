## Plan

**The evidence so far.** `conf-typing builds` should take 0 s when nothing in `conf-typing/` changed. It has failed its 15 s budget on unrelated commits:
- RC-01 step 5: 17 s. It rebuilt in 2 of the 8 runs before it.
- RC-02 step 2: 77 s, after a branch switch (receipt `rc02-step2-ci`).
- RC-02 step 3: 19 s (receipt `rc02-step3-ci`). `conf-typing/.lake/build/lib/lean/ConfTyping.olean` is stamped 22:03:45, inside that run.

Each time the rerun took 0 s.

**Hypotheses, none tested.**
- The root workspace, which requires `conf-typing`, builds into the same `.lake` with a different trace. Jobs that build the root workspace outside CI (`tools/axioms.sh`, a branch switch) leave a trace that `conf-typing`'s own `lake build` does not accept.
- File timestamps from `git checkout` change Lake's input hashes. Lake hashes contents, so this is less likely.

**Ring 0:** the fix touches `tools/ci.sh` or the lakefiles. It is the user's key.
