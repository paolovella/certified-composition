## Plan

**The evidence so far.** `conf-typing builds` should take 0 s when nothing in `conf-typing/` changed. It has failed its 15 s budget on unrelated commits:
- RC-01 step 5: 17 s. It rebuilt in 2 of the 8 runs before it.
- RC-02 step 2: 77 s, after a branch switch (receipt `rc02-step2-ci`).
- RC-02 step 3: 19 s (receipt `rc02-step3-ci`). `conf-typing/.lake/build/lib/lean/ConfTyping.olean` is stamped 22:03:45, inside that run.

Each time the rerun took 0 s.

**Hypotheses, none tested.**
- The root workspace, which requires `conf-typing`, builds into the same `.lake` with a different trace. Jobs that build the root workspace outside CI (`tools/axioms.sh`, a branch switch) leave a trace that `conf-typing`'s own `lake build` does not accept.
- File timestamps from `git checkout` change Lake's input hashes. Lake hashes contents, so this is less likely.

**Ring 0:** the fix touches `tools/ci.sh` or the lakefiles. It is the user's key.

## Log
- 2026-11-09, **the cause, reproduced on demand.** `conf-typing/ConfTyping/LAdapter.lean` imports `LCore`, and `conf-typing`'s lakefile requires `l-core` by path. So the CI step "conf-typing builds" recompiles `LAdapter`, and the modules after it, whenever `LCore`'s compiled output changes.
  - Seen: a new declaration added to `l-core/LCore/Slice2/Add.lean`, `l-core` built, then `cd conf-typing && lake build` took 16.3 s (`ConfTyping.SpecL`, `TenantL` and the rest rebuilt). After restoring the file, it took 18.5 s again.
  - A comment-only change leaves the `.olean` unchanged and rebuilds nothing (0.14 s), which is why some runs took 0 s.
  - **So the step fails on the first CI run after most `l-core` commits:** 77 s, 19 s, 15 s and 19 s over RC-02 steps 2 to 5, and 0 s on each rerun. Neither hypothesis above was the cause. Both are withdrawn.
  - **Fixes, for the user's key:**
    - (a) the step's budget covers the rebuild, about 25 s on this box;
    - (b) `LAdapter`, which joins the two packages, leaves `conf-typing`'s default target for its own step;
    - (c) CI builds `l-core` first, and the `conf-typing` step's budget is measured after an `l-core` change.
  - I would choose (b): the step then times `conf-typing` alone, as its name says.
