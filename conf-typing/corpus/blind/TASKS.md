# Tasks for a secure request-handler language

1. [SAFE] A handler looks up a user profile by id after checking the caller may read that profile. Return the profile only when the check passes. [every access must be authorized]
2. [SAFE] A login handler compares a submitted password against a stored credential and returns success or failure. The comparison must take the same time regardless of how many characters match. [must not leak the password through timing]
3. [SAFE] A handler allocates a buffer, fills it with a formatted response, writes it to the client, and frees it before returning on both the success and error paths. [no use-after-free or leak; free on every path]
4. [SAFE] A handler reads a row count parameter, allocates that many record slots up to a fixed maximum, populates them, and frees the whole block once emitted. [no out-of-bounds write; free on every path]
5. [SAFE] A handler builds a SQL query selecting an order by its id, binding the untrusted id as a parameter rather than concatenating it. [no injection into the database sink]
6. [SAFE] A handler takes a user-supplied filename, confirms it resolves within an allowed directory, then opens it. Reject names that escape the directory. [no path traversal into the file-path sink]
7. [SAFE] A handler writes an audit line combining the request method and a sanitized user agent to the log. Control characters in the input must not reach the log. [no injection into the log sink]
8. [SAFE] A handler renders a comment into an HTML page, escaping the untrusted comment text before it is placed in the markup. [no injection into the HTML sink]
9. [SAFE] A handler holds an API token used to call an upstream service and must never place that token into the response body or the log. [must not leak the token to public output]
10. [SAFE] A handler decides whether to grant access using a role flag, never using the secret session key, so that which branch runs reveals nothing about the key. [no secret may decide a branch]
11. [SAFE] A handler retries a flaky downstream call at most five times with a fixed delay, then gives up. The retry loop is bounded. [loops must be bounded]
12. [SAFE] A pagination handler returns at most one page of results given an offset and a page size capped at a fixed limit. [loops must be bounded; no out-of-bounds read]
13. [SAFE] A handler checks a cache for a key, returns the cached value on a hit, and on a miss computes the value, stores it, and returns it. [every access must be authorized before store]
14. [SAFE] A batch handler processes a bounded list of job ids, authorizing each job before acting on it, and skips any the caller may not touch. [every access must be authorized]
15. [SAFE] A handler parses a request into fields and then emits a normalized version of those fields, allocating the output buffer and freeing it after sending. [no use-after-free; free on every path]
16. [SAFE] A handler must free a buffer exactly once even though it can fail at two points after allocation. Ensure no path frees it twice. [no double free]
17. [SAFE] A handler iterates over a fixed-size array of connection records, closing each open one, with the index staying within bounds. [no out-of-bounds access; loops bounded]
18. [SAFE] A handler conditionally allocates a scratch buffer only when a flag is set, and frees it only on the paths where it was allocated. [no use-after-free, no free of an unallocated buffer]
19. [SAFE] A handler stores a submitted note under a key now and, in a later request, reads that note back and returns it to its owner after an authorization check. [every access must be authorized]
20. [SAFE] A handler runs nested loops over a bounded grid of rows and columns to aggregate counts, with both loop counts fixed by constants. [loops must be bounded]
21. [SAFE] A handler validates that a quantity field is within an allowed range and returns a typed error when it is not, freeing any resources acquired so far. [free on every path; no out-of-bounds]
22. [SAFE] A handler hashes a password with a salt and stores only the hash, never retaining or returning the plaintext password. [must not leak the password]
23. [SAFE] A handler constructs a shell-free system action by selecting from a fixed set of allowed operations keyed by an untrusted command name, rejecting unknown names. [no injection into the shell sink]
24. [SAFE] A handler copies at most N bytes of untrusted input into an N-byte buffer, truncating rather than overflowing. [no out-of-bounds write]
25. [SAFE] A handler returns early with a denial response the moment an authorization check fails, before touching the resource. [every access must be authorized]
26. [SAFE] A handler accumulates a response in a growable buffer across a bounded loop and frees it once after the final send. [free on every path; loops bounded]
27. [SAFE] A handler compares a submitted one-time code to the expected code in constant time and clears both from memory before returning. [must not leak the code through timing]
28. [SAFE] A handler validates and canonicalizes a redirect target against an allowlist of hosts before issuing the redirect. [no open redirect; no injection into the location sink]
29. [SAFE] A handler reads a length-prefixed message, rejecting any length that exceeds the buffer capacity before reading the body. [no out-of-bounds read]
30. [SAFE] A handler releases a database connection it acquired even when the query it runs raises an error partway through. [free on every path]
31. [SAFE] A handler that calls a helper function to authorize a resource, and only proceeds if the helper reports success. [every access must be authorized; expressible with functions]
32. [SAFE] A handler maintains a record of a user with name, role, and quota fields, updating the quota only after checking the caller owns the record. [every access must be authorized; expressible with records]
33. [UNSAFE] A handler builds a SQL query by concatenating the untrusted search term directly into the WHERE clause and sends it to the database. [must reject: injection into the database sink]
34. [UNSAFE] A handler opens the file named exactly by the client-supplied path with no containment check, allowing `../` to escape the directory. [must reject: path traversal]
35. [UNSAFE] A handler frees a response buffer and then, on the error path, writes a trailing byte into the same buffer before returning. [must reject: use-after-free]
36. [UNSAFE] A handler frees a buffer in a loop body that can run more than once over the same pointer. [must reject: double free]
37. [UNSAFE] A handler returns the stored session key in the response body for debugging when a verbose flag is set. [must reject: secret leaks to public output]
38. [UNSAFE] A handler takes a different, slower branch when the first byte of the submitted token matches the secret, so timing reveals the secret. [must reject: secret decides a branch and leaks through timing]
39. [UNSAFE] A handler reads records in a loop that continues until a terminator is found in untrusted input, with no upper bound on iterations. [must reject: unbounded loop / resource exhaustion]
40. [UNSAFE] A handler accesses a resource by id and returns it without ever checking the caller is allowed to read it. [must reject: missing authorization]
